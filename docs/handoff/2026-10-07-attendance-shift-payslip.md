# 申し送り：打刻・シフト・給与明細のテスト運用（2026-10-07 壁打ちセッションより）

## 目的
打刻・シフト・給与明細を急いでテスト運用する。IH-PLATFORM を全社データの「1か所」（正本）にしていく第一歩。

## 決まったこと
- 新システムは作らない。IH-PLATFORM に機能を足す
- スタッフへの通知は、既存の LINE Messaging API チャネル「IKKOU HOLDINGS NEWS」を使う。全友だちへの一斉配信は、マイページ開設の案内1回だけにする。それ以外は「LINE連携済み・在籍中」のスタッフにだけ送る
- LINE は通知と入口の役だけにする。入力はポータル画面で行う
- 権限は「役割ごとのデフォルト＋モジュールごとの ON/OFF」にする（下の表）
- 打刻・シフトのロジックは、黒田さんから受け取った移植仕様（夜営業向け勤怠・シフト・給与システム）に沿う。日付処理（営業日は朝5時で切り替え、`date` 型はJST、`timestamptz` 型はUTC）、15分丸め、深夜割増、単発QRトークン、打刻修正ページの考え方を流用する

## 現状（コードで確認済み）
- `.env.local` に Supabase の接続キーを再設定済み（2026-10-07）。service role・anon とも接続OK。anon からは staff が0行しか見えない（RLS は効いている）。staff は49行

### 2. 打刻（パイロットは一鴻を提案中。未確定）
- 作る：QR掲示ページ（掲示キーで保護）、単発トークン（発行→LINEで本人確認→打刻で使い切る。条件付きUPDATEで同時使用を防ぐ）、出勤・退勤、休憩分数の入力、管理者用の勤怠一覧、打刻修正ページ
- 後回し：退勤チェックリスト、打刻画面でのお知らせ表示
- GPS は判定結果を記録するだけで、打刻は止めない
- `attendance` には `store_id` を持たせる（将来の兼務や他店への応援に備える）
- 一意制約は当面 `unique(staff_id, date)` でよい。ただし「1人1日1店舗」の制約になることを承知しておく

#### 2-a. 店舗マスタと店舗ごとの打刻QRページ（黒田さん要望 2026-10-07）
- 既存の店舗マスタ（`stores`）に列を足す。新しい表は作らない
  - `code`：店舗のイニシャル。英大文字2〜4文字、一意。URLに使うので、一度使い始めたら変更禁止（iPadのブックマークと過去の記録が壊れるため）
  - 掲示キー（ランダムな長い文字列。保存はハッシュ）と、再発行ボタン
  - 営業日の切り替え時刻（既定5時）、シフト時刻の初期値
- コードは signal-playbook と揃える。**一鴻＝IKK は確定（2026-10-07 黒田さん）**。それ以外は案の段階：NEK（郷彩 根っこ）／OBZ（obanzai）／CFM（COOKIE for MEN）／CHM（COOKIE熊本）／ICH（「一」）／STY（STYLE-US）／HD（IKKOU HOLDINGS）
- 掲示ページ：`/punch/display/[code]?key=…`。iPadで開きっぱなしにする。ログインは不要
  - code だけのURLだと店の外からでも開けてQRを取れてしまうので、掲示キーを必ず照合する
  - QRは「誰かが読んでLINEで本人確認した瞬間」か「5分経過」の早いほうで次のものに切り替える。掲示ページは数秒ごとに状態を確認する
  - 画面には店舗名・時計・QRの残り時間・直近の打刻（「○○さん 出勤 19:28」）を出す
  - トークンに `store_id` を持たせ、勤怠の店舗はトークンから記録する（スタッフの所属店舗からは取らない）。他店への応援にも対応できる
  - 通信が切れたら掲示ページにエラーを出し、打刻修正ページで後から直す運用にする
- iPadの運用：ホーム画面に追加し、アクセスガイドで固定、自動ロックはOFF、常時充電
- 参考：旧 Firebase 版の `~/ih-payroll-system/public/timework/tablet-clock.html` は、タブレットでスタッフ名を選ぶ方式（QRの切り替えはなし）。今回は採用しない

### 3. シフト（打刻と同時に）
- 先に作る：管理者（または店長）が確定シフトを入力する週表示と、スタッフの閲覧画面
- 次に作る：シフト希望の提出（`shift_request_submissions` で未提出と全日×を区別する）と、未提出者へのLINE催促（昼12時、締切3日前と前日の2回、締切後は店長へ未提出者一覧）

### テスト運用のルール
- 給与1回分は今のやり方と並行して運用する。打刻から給与への自動連携はテスト中は行わず、打刻の集計結果と今の給与を突き合わせるだけにする
- 時間外割増（1日8時間・週40時間を超えた分は×1.25 ほか）は、移植仕様には入っていない。自動連携の前に必ず入れる
